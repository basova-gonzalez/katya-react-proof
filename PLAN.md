# UNKNW Agent-Ready Brief — рабочий план

**Статус:** концепция принята Кейт в треде `codex://threads/01a03915-c048-78c2-bde1-8073d042627c`. 16 сентября 2026 проект перенесён в отдельную рабочую папку: копия сверена, исходный каталог удалён с явного разрешения Кейт. Кейт уточнила направление визуала и закрытого показа, затем прямо разрешила приступить к реализации. Локальная версия собрана и проверена в Chrome после разрешения Кейт. После её замечаний делается третий визуальный проход. GitHub, Vercel и отправка сообщения UNKNW не начинались.

## Цель и граница

Создать небольшой одностраничный интерактивный прототип на английском, чтобы показать команде UNKNW три умения Кейт: работу в React/Next.js/Vercel, умение продолжить их существующий визуальный язык и проектирование сценария, полезного человеку и агенту. Экран должен выглядеть как аккуратное расширение их интерфейса; это независимый концепт, не официальная работа студии и не изменение их настоящего приложения. На странице должна быть заметная подпись: “An independent UX experiment inspired by UNKNW’s public site. Not affiliated with or endorsed by UNKNW.”

Работа живёт в самостоятельном проекте `01_Projects/unknw_09-2026` с отдельной будущей Git-историей. Материалы `Career Profile 2026` в него не входят. Первую версию держать в приватном личном GitHub-репозитории и показывать через защищённое превью Vercel. Черновик обращения предусмотрен планом, но отправление сообщения UNKNW не разрешено.

## Что входит в прототип

1. **Hero и три входа:** `start a project`, `find relevant work`, `give an agent context`. Каждый вход открывает или прокручивает работающий сценарий.
2. **Brief composer:** короткий intake о типе задачи, стадии продукта, проблеме ясности и сроках. Выход — понятный человеку текст и компактный JSON.
3. **Structured work catalogue:** небольшой полностью синтетический каталог. Фильтры по типу задачи, индустрии и результату работают с клавиатуры и меняют карточки без перезагрузки.
4. **Freshness layer:** дата проверки, статус `current` / `review due` / `archived` и версия каталога видны на экране. Это демонстрационная редакционная модель, а не автоматический мониторинг сайта UNKNW. Даты и статусы синтетических материалов явно обозначают данные примера, без притворного обновления при каждой сборке.
5. **Agent context:** описание демонстрационного проекта, подходящие синтетические работы, правила маршрутизации и структурированный бриф собраны в копируемый пакет. При отказе Clipboard API текст остаётся доступен для ручного копирования.
6. **Завершение:** компактный футер с явным статусом независимого прототипа. Рекламный финальный экран и контакт-заглушка убраны по последнему уточнению Кейт. Никакой формы отправки, CRM или настоящего контакта UNKNW.

Данные формы живут только в состоянии текущей вкладки. Нет реального AI-вызова, сервера, базы, API-ключей, авторизации, аналитики, почты или отправки данных наружу.

## Визуальный подход

Максимально близко изучить и воспроизвести визуальную систему публичного сайта: графитовый фон, тёплый светлый текст, красно-оранжевый акцент, крупную типографику, моноширинные метки, редакционную сетку, плотность, движение и состояния элементов. Реализация и новые компоненты — собственным кодом. Кейт разрешила реализацию всей локальной страницы; до публикации требуется визуальная проверка рядом с оригиналом и её оценка. Использование фирменных шрифтов и изображений зависит от прав на конкретные файлы; вопрос об изображениях разобрать до их включения в онлайн-превью. Пометка о независимом концепте остаётся видимой.

## Данные и машинное представление

`CatalogItem`: `id`, `title`, `summary`, `services`, `industry`, `outcomes`, `verifiedAt`, `contentStatus`, `agentTags`; версию каталога хранить рядом с набором. `BriefPayload`: `intent`, `projectType`, `stage`, `clarityNeed`, `timeframe`, `summary`, `recommendedNextStep`, `generatedAt`. Сборку брифа и фильтрацию вынести в чистые TypeScript-функции.

Использовать существующий starter: Next.js 16.3.2, React 19, TypeScript, App Router. Визуальную систему строить на CSS-переменных и явных классах; Tailwind может остаться вспомогательным. Шрифты входят в сборку из разрешённых пакетов, без зависимости от Google Fonts во время работы страницы. Добавить metadata, `robots.ts`, `sitemap.ts`, JSON-LD и `public/llms.txt`, которые описывают **этот независимый прототип**. Удалить starter-содержимое из публичного интерфейса.

## Критерии готовности локальной версии

- Три входа ведут к нужным сценариям; brief composer не генерирует пустой результат и показывает понятную подсказку у обязательных полей.
- Каталог фильтруется корректно; JSON соответствует видимому брифу и содержит только введённые пользователем или явно демонстрационные данные.
- Экран работает на 360 px, 768 px и широком desktop; все интерактивные элементы доступны с клавиатуры, имеют подписи и видимый фокус; движение учитывает `prefers-reduced-motion`.
- Проверены фильтрация и сериализация, `npm run lint`, `npm run build`; проведён ручной проход основных сценариев и ограничения Clipboard API.
- Нет секретов, чужих ассетов, неразрешённых материалов, ложной аффилиации и внешней отправки данных.
- Проверка в Chrome проведена после явного согласия Кейт на просмотр и сохранение изображений вкладок. Остальные непройденные проверки отмечать честно.

## Уточнение от 16 сентября — визуал и закрытый показ

16 сентября Кейт уточнила цель пруфа: запрос ищет product designer, способного менять UX/UI прямо в готовом React-приложении, сохраняя высокий визуальный уровень. Решение — стремиться к точному продолжению визуальной системы UNKNW и сначала показывать результат через приватный GitHub и защищённое превью. Независимый статус концепта сохраняется.

Сделать новый экран так, будто он входит в существующий сайт: изучить типографику, цвета, сетку, ритм и поведение элементов, реализовать собственным кодом и проверить рядом с оригиналом. Локальная страница собрана по новому разрешению Кейт; визуальное качество нужно оценить до публикации и отправки пруфа.

По состоянию на 16 сентября у Vercel Hobby **нет встроенного пароля** для проекта. [Vercel Authentication](https://vercel.com/changelog/protect-production-deployments-for-free-on-every-plan) теперь может закрывать все деплои бесплатно; [Shareable Link](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/sharable-links) даёт внешнему зрителю доступ по специальной ссылке (на Hobby один такой активный линк). Это доступ по ссылке, а не пароль. [Password Protection](https://vercel.com/changelog/password-protection-now-costs-20-per-project-per-month-on-pro) с 9 сентября доступна на Pro за дополнительную плату $20 в месяц за проект. Отдельный приватный репозиторий GitHub можно подключить к личному Hobby-проекту Vercel; [ограничение](https://vercel.com/docs/git) касается приватных репозиториев организаций. Если закрыть только Vercel, публичный GitHub всё равно откроет код и вложенные ассеты.

Выбран приватный GitHub и защищённое превью; перед деплоем надо проверить доступность этих функций в аккаунтах Кейт и определить, кому выдаётся ссылка. Вопрос об использовании изображений остаётся открытым.

## Последнее уточнение Кейт — цель кейса и структура

Цель этой страницы — коротко подтвердить требуемые навыки: точное чтение визуальной системы UNKNW, изменение логики сценария прямо в React и подготовку контекста для LLM. Первый экран — личное обращение к Мише на английском; Кейт отвергла русский заголовок и использованный для него шрифт. Для этого достаточно hero, одной галереи и рабочего сценария «запрос → бриф → LLM-контекст»; рекламный финальный экран и повторная галерея удалены.

Кейт отдельно указала: обложки должны начинаться на одной высоте, подписи к ним должны быть короткими, навигация доступна без раскрытия меню, фоновые линии заметно движутся. Это последнее указание заменяет прежнюю идею выводить под каждой обложкой дату, статус, описание и теги. Структурные поля остаются в демонстрационных данных и контекстном пакете, но не загружают визуал каталога.
